WHY DEVELOPER

새 기술도 기초부터 직접 확인하면서 익혀 왔어요. 전공동아리 AILab에서 파이썬 기초를 다지고, 2년 동안 데이터 분석·AI 모델링을 하고 Flask·Streamlit으로 서비스를 배포했어요.

여러 프로젝트를 하면서 제일 오래 붙잡고 있던 문제는 사용자가 기다리거나 요청이 실패하는 순간이었어요. 그래서 AI 모델을 사용자가 멈춤 없이 쓸 수 있는 서비스로 연결하는 AI 에이전트 백엔드 개발자를 목표로 하고 있어요.

AI 기능을 만드는 데서 끝내지 않고, 직접 배포해서 운영하고, 느려지면 재서 고쳐요.

STRENGTHS

짐작 말고 측정

문제가 생기면 고치기 전에 로그와 지표부터 봐요. 표정 분석 모델이 안 오르던 원인도, 학습이 느리던 원인도 재 보니 모델이 아니라 데이터와 실행 환경이었어요.

모델과 서버를 같이 봐요

AI 모델 성능만큼 서버 구조도 중요해요. LLM 추론 때문에 로그인까지 멈추던 서버를 역할별로 나눠, 답을 만드는 동안에도 다른 기능이 바로 돌게 했어요.

직접 배포하고 운영해요

Docker(Ubuntu·AWS) 환경을 만들고 Cloudflare·Vercel 배포를 자동화했어요. 지금도 서비스 4개를 직접 띄워 두고 운영하고 있어요.

PROBLEM SOLVING

Arda · 백엔드

동시 면접자가 늘수록 면접이 느려지던 문제

문제
동시 면접자가 늘수록 다음 질문이 나오기까지 시간이 점점 길어졌어요.
원인
처리 흐름을 단계별로 재 보니, 다음 질문이 이전 답변의 STT 변환이 끝나기를 기다리느라 멈춰 있었어요.
해결
면접은 STT를 기다리지 않고 계속 진행하고, STT 변환은 async 비동기 대기열에서 순서대로 처리하게 바꿨어요.
결과
동시 면접 4명 기준 처리 시간 50% 단축

Arda · AI 모델

아무리 학습해도 오르지 않던 표정 분석 정확도

문제
표정 분류 ViT 모델의 정확도가 좀처럼 오르지 않았어요.
원인
모델을 바꾸기 전에 표정별 결과를 확인해 보니 '역겨움' 정밀도가 5.9%였고, 원인은 모델이 아니라 부정확한 데이터 라벨이었어요.
해결
라벨을 교체하고 학습 설정을 바로잡았어요.
결과
전체 정확도 74.9% → 86.2%, 역겨움 정밀도 5.9% → 64.2%

양동이 · 서버 구조

LLM이 답하는 동안 로그인까지 멈추던 서버

문제
챗봇이 답을 만드는 동안 로그인, 시간표 조회 같은 일반 요청까지 같이 느려졌어요.
원인
동기 처리하는 Flask 서버 하나가 학사 데이터와 LLM 추론을 함께 맡고 있었어요.
해결
Flask는 인증·학사 데이터, FastAPI는 벡터 검색·LLM 추론만 맡게 나누고, 데이터도 종류별로 MySQL·MongoDB·ChromaDB에 나눠 담았어요.
결과
LLM이 답하는 중에도 로그인·시간표 조회가 바로 처리됨

다누시스 현장실습 · Vision AI

주말 내내 돌렸는데 12에폭밖에 안 된 학습

문제
객체 탐지 모델을 주말 내내 학습시켰는데 12에폭밖에 진행되지 않았어요.
원인
학습 로그를 보니 GPU가 아니라 CPU로 학습되고 있었어요.
해결
GPU로 전환하고, YOLOv8 n·m·l 세 모델을 val loss로 비교해 약 90에폭의 가장 안정적인 모델을 골랐어요. 트랙터·스쿠터 오탐지는 해당 클래스 데이터를 보완해 다시 학습했어요.
결과
학습이 정상 속도로 돌고, 오탐지가 잦던 클래스까지 보완한 모델 선정
